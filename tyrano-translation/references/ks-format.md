# .ks 剧本格式与回写规则（TyranoScript / TyranoBuilder）

Tyrano 剧本是 UTF-8（本仓库样本带 `\r\n` 行尾）的标签文本，无加密。
TyranoBuilder 生成的脚本结构高度规整，文本定位靠**结构**而不是字符串表。

## 显示文本模型

```
[tb_start_text mode=4 ]
#【ユリ】              ← 名字行：说话人标签（空 # = 旁白名栏清空，是结构）
「对白第一行…[r]        ← 文本行（物理行）；[r] 强制换行
对白第二行…」[p][vs]    ← [p] 翻页等待、[vs] 语音挂接
[_tb_end_text]
```

- **一条译文 = 一个物理行**。多行对白已被 `[r]` 拆开，索引序 = 剧情序，
  译文里绝不允许出现真实换行或字面 `\n`（换行一律用 `[r]` 标签）。
- 名字行是引擎级显示文本：解析器（`kag.parser.js`）把 `#XXX` 变成 `chara_ptext` 标签，
  写进消息窗名字区（`chara_name_area`）和 **backlog 说话人栏**
  （`<b class="backlog_chara_name">`）。消息窗里的名牌图是另一套
  `name_tag_img storage=*.png` 图片，与 # 行互不影响；要不要译 # 行
  （backlog 中文 vs 名牌图日文的一致性）是项目决策，写进翻译指南。
- 旁白块以裸 `#` 开头，**不进模板**（翻译成任何非空值都会显示一个假名字）。

## 语音挂接（voiceplay_ex / brainlabo_voconfig）—— 名字行是语音键

引擎按**名字行精确内容**查角色语音注册表 `kag.stat.map_vo.vochara`（chara_ptext 里
`vochara[pm.name]` 命中 → playse `vostorage.replace("{number}", number++)`）。
注册发生在剧本顶层的 `[brainlabo_voconfig type=".ogg" number=… buf=… name="【ユリ】"
storage="vo/lily"]`，通常集中在 **boot 剧本**（本仓库 first.ks 6 条 = 全游戏注册），
**结局/分支可能另文件重注册**（end2.ks 3 条，带续接编号）。注册 `name=` = 原文 `#` 行。

**翻译后语音必断**：`#【ユリ】` 译成 `#【尤莉】` 后 `vochara[【尤莉】]` 查不到 →
静默不播、**编号也不再推进**（后续该角色所有台词编号全错位）。注册行在
tb_start_text 块外，文本工具不提取，需单独修。

**修复**：把注册名同步成译文说话人名（一一对应，见译文名字行普查）。
`python $S/voice_namefix.py <映射.tsv> <改的.ks...>`，映射两列：
`【ユリ】\t【尤莉】`。只改 `[brainlabo_voconfig]/[voconfig]` 的 `name="…"`，保留原 EOL。
改的是结构行 → 改后不要对原 tpl 跑 ks_tool verify（必然报结构行差异），用
`grep 'brainlabo_voconfig'` 核对注册名 + 真机抽查代替。改哪个文件由普查
（哪个剧本含 `[brainlabo_voconfig]`）决定；改完把该文件加进 tpatch payload。
未注册的角色（本仓库【カーター】无 voconfig）本来就没语音，不用管。

## 引擎解析规则（kag.parser.js，回写安全的依据）

- `;` 行注释、`/* */` 块注释、`@` 行首标签、`*` 标签（label）都是结构。
- 行内 `[` 开启标签扫描（引号内的 `[` 不算），`\` 转义下一字符，行首 `_` 被吃掉。
  因此**译文行首不得出现 `;` `@` `*` `_`**（rebuild 已加门禁）。
- 标签按行解析，纯标签行（如单独 `[p][vs]`）不产生文本。

## 行内标签（本仓库语料普查：只有 5 种）

| 标签 | 语义 | 译文处理 |
| --- | --- | --- |
| `[p]` / `[vs]` | 翻页等待 / 语音挂接（几乎总在行尾成对） | 原样保留 |
| `[r]` | 强制换行 | 原样保留，位置可随译文移动 |
| `[l]` | 单击等待 | 原样保留 |
| `[ruby text=ナ]` | 注音，作用于**紧随其后的字符** | 保留；可按中文发音重排 ruby 与正文的位置，但标签出现顺序不能变 |

- **rebuild 的核心门禁：译文的标签序列必须与原文完全一致**（内容可移动，
  顺序和个数不能变）。缺标签=台词在游戏里被悄悄改变行为，多/错标签=引擎误解析。
- 原文行尾的 `[p][vs]` 是"翻页+语音"结构，漏掉会破坏既读/语音/等待。

## 换行与行尾

- 原始 `.ks` 是 `\r\n`。工具统一归一化为 `\n`（引擎对每行 `$.trim`，写 `\n` 安全）。
- **事故**：`load_ks` 未归一 `\r` 时，行内残留 `\r` 写进 TSV，Python 文本模式
  （universal newlines）把 87 行读成 151 行。此坑已修死，但自造 TSV 处理代码时
  仍要警惕 `\r`。
- 消息窗自动折行，翻译时**不需要**用 `[r]` 模仿日文断行位置；`[r]` 只保留原文
  已有的（如对话的分行节奏）。

## 翻译工作区 TSV

- tpl（3 列）/ work（4 列）/ proof（6 列）：`索引 \t 说话人 \t 日文原文 [\t 初译 [\t 校对 \t 备注]]`。
- 名字行的**说话人列恒为空**、原文列是名字本体（`【ユリ】`，无 `#`）；
  rebuild 回写时自动补 `#`。
- 说话人列取自块内最近的名字行，只作语气参考，不参与回写。

## 场景外的日文文本（按需另行处理）

| 位置 | 内容 |
| --- | --- |
| `tyrano/lang.js` | 引擎系统弹窗（存读档确认、错误提示等） |
| `tyrano/html/config*.html`、`save.html`、`extra*.html` | 设置/存档/鉴赏界面 UI 文本（含 HTML 内嵌 JS 拼接） |
| `data/scenario/config.ks`、`system/*.ks` | `[iscript]` 里的 JS/HTML 字符串（设置项等） |
| `data/others/plugin/ex/name_tag/*.png` 等 | 名牌图、标题 LOGO 等图片文本，需改图 |
| `*.tbp` | TyranoBuilder 编辑器元数据，运行时不加载，不用译 |

系统/插件脚本里的文本都在 JS 字符串或 HTML 里，**不在 tb_start_text 块内**，
本工具链不提取；要汉化 UI 时单独处理并同样走「改前备份、改后真机冒烟」。
