# SiglusEngine 系游戏文本汉化 · 完整流程手册

> 从零到可发布 Scene_new.pck 的标准链路。所有原版文件全程只读，产物一律写新文件。
> 格式细节见 `pck-format.md` 与 `ss-format.md`；本文只讲流程与纪律。

```
game Scene.pck ──(1) pck_tool unpack──▶ unpacked/ (*.ss + manifest.tsv)
unpacked/*.ss ──(2) make_template──▶ tpl/(原文,只读) + work/(译文骨架)
unpacked/     ──(2b) extract_text──▶ text/(剧情顺序可读全文，译者语境)
work ──(3) 初译（只填最后一列；多章可多代理并行，见 §7）
work ──(4) validate_text --lines=1 ──▶ 行宽门禁
work ──(5) make_proof──▶ 对照稿 proof + preview/read 两份阅读稿 ──(6) 人工校对(第5/6列)
work+proof ──(7) validate_text──▶ 终校门禁（必须全绿）
全部章节交付后: validate_text(逐文件) + check_structure(--tpl 全量) + check_terms
原ss + work + proof ──(8) ss_tool rebuild──▶ 译好的 ss
        (9) ss_tool verify──▶ 内容级验证（必须 MATCH）
改好的 *.ss 放回 unpacked/ ──(10) pck_tool pack──▶ Scene_new.pck ──▶ 替换上机
        (11) 回读解包比对 + 真机抽查
```

## 0. 首次适配清单（新游戏必做）

1. 找到本游戏的 16 字节密钥并 `pck_tool.py probe` 验证（途径见 pck-format.md §3）；
   密钥存进项目工作区 `workspace/key.txt`。
2. 全量解包确认 0 失败；`strings` 抽查几个场景确认文本可读、无乱码。
3. **实测引擎硬限制**：消息窗每行字数上限与自动折行行为（截图量字数）；确认％Ｂ翻页、
   【名字】「台词」形态在目标游戏里的实际表现。
4. 小规模伪翻译冒烟：1~2 个场景填全角Ａ假文 → rebuild → verify → pack → 上真机，
   确认部署方式（直接替换 Scene.pck？有无 patch 叠加？）、显示、翻页、既读判定全部正常；
   全部结论记入项目笔记。**动 Scene.pck 前务必备份原版。**
5. 译前通读与指南生成（见 §1）后再开翻。

## 1. 译前通读与指南生成（开工前必做）

> 目标：把"全书视野"沉淀为三份产物——**剧情梗概、翻译指南、terms.tsv**，
> 让后续分章翻译的执行者不需要（也不应该）拥有全书上下文。

为什么必做：

- 术语/称呼一旦在初译中各自漂移，校对期统一返工的成本远高于开工前定名。
- 伏笔、双关、叙事诡计、跨章回环梗只有通读全书才能被发现，并写成硬规则。
- 分章译者若直接拿全书文本，容易把后文才揭示的信息提前泄露进前文译文（破坏叙事诡计）。
  正确做法：全书知识浓缩成规则放进指南，译者只读本章 + 简报。

做法（少量代理即可，与翻译阶段的 10+ 并行不同）：

1. `extract_text` 导出按剧情顺序的可读全文（每个 .ss 一个文件）。
2. 分派少数"读者"代理逐章/逐数章通读，按固定结构汇报：分章梗概（数句）、出场人物
   与称呼、新术语提案（`原文\t建议译文\t依据`）、伏笔/双关/回环标记、疑难句。
3. 主控汇总各章报告：合并去重术语提案并**统一定名拍板**，产出：
   - **剧情梗概**：分章摘要、人物关系、伏笔与叙事诡计清单、时间线；
   - **翻译指南**：术语总表、称呼对照、角色声纹（自称/语气/口癖/笑声）、文体规范、
     高风险场景处理规则、回环梗清单；
   - **terms.tsv**：指南术语表的机器可读版（`原文\t规范译文[\t禁用形式]`），
     直接作为 `check_terms.py` 的门禁输入。
4. 三份产物即《翻译简报》（BRIEF）的原料；之后的并行分派见 §7。

⚠ 读者代理需要**全书视野**（剧透无妨），译者代理恰恰相反——两个阶段的上下文策略相反。

## 2. 工作区与三分离设计

| 目录 | 内容 | 纪律 |
| --- | --- | --- |
| unpacked/ | 解包产物（*.ss + manifest.tsv） | 只读（仅"把译好的 ss 拷回来封包"例外）。manifest 不得增删改名 |
| tpl/ | 原文模板（索引\t说话人\t日文） | 只读参考，可随时重生成 |
| work/ | 译文文件（…\t日文\t译文） | 译者只填最后一列；生成器绝不覆盖已存在文件 |
| proof/ | 对照稿（索引\t说话人\t日文\t初译\t校对\t备注）＋ preview/read 两份剧情顺序阅读稿 | 校对只动第5/6列；第5列留空=采用初译 |
| out/ 或 Scene_new.pck | 重建/回封产物 | 可随时删除重来 |

- 生效译文规则统一为：**校对列非空 > 初译列**；多文件合并时后者按索引覆盖前者。
- 行序 = 字符串表索引升序 = 剧情顺序——这是 Siglus 相比 KiriKiri 的天然优势：
  译者从模板第一行读到最后一行就是剧本顺序。

## 3. 翻译阶段纪律

- **索引是唯一锚点**：TSV 第 1 列是字符串表索引，字节码按它引用字符串。批量改稿前用
  `awk -F'\t' '$1==N'` 回验目标行内容，防止把行号当索引用导致整段错位。
- **不要写任何换行记号**。Siglus 消息窗自动折行、％Ｂ 串负责翻页；译文含真实换行或字面
  `\n` 都会被 rebuild 拒绝。写入纪律照旧：一律脚本文件 + raw 字符串，禁止 heredoc/
  命令行直写大段译文；未译条目保持列数（留空的最后一列）。
- 行宽按真机实测值设置（`--width=N --lines=1`）；消息窗自动折行的引擎（Siglus 实测）超长串可安全容纳，超宽仅警告不阻断（`--soft`），但**换行记号永远致命**。译文仍宜短于原文。
- **说话人列是启发式推断值**，可能为空或误判：空＝旁白/独白或【名字】「台词」合一形态。
  语气归属以它为参考而非铁律，存疑时看 preview 上下文。
- 全角标点、全角英数字母/数字（与 UI 宽度匹配）；术语表先行并全程冻结（check_terms 落地）。
- 同一台词跨章重复出现时措辞一字不差（回忆回环梗）；伏笔不得提前泄露——后续章节才揭示的
  信息，前文译文与注释都不写破。译者注只在"不加注就无法理解"时使用，格式统一且从简。
- 引号规范示例（按目标 UI 习惯定稿）：对白外层「」、内层引用『』；旁白不加「」；
  弯引号 " " ‘ ’ 一律替换。

## 4. 校对阶段

### 4.1 校对总清单（五个维度，缺一不可）

1. **信达雅**：语句是否忠实原意、通顺自然、有雅韵——拒绝机翻腔（逐字直译、"的/了/吧"
   连篇、欧化长句）；原文俏皮处要译出笑点，抒情处要有相应的节奏与韵味。
2. **上下文与人称**：上下文是否通畅；人称指代是否正确（谁属谁、谁对谁做）；行文是否
   符合说话人的性格（自称、语气、敬语水准等角色声纹）。说话人列为空＝旁白/独白或内嵌名。
3. **译法一致性**：不同译者对同一个词（特别是专有名词、术语、称呼）是否产生了多种译法
   ——用跨章搜索逐一比对并统一为定稿。例外：语气词及依据人设刻意差异，宽容尺度写入
   项目笔记。
4. **伏笔 / 谐音 / 双关 / 梗**：是否按翻译指南正确处理；跨章回环呼应句措辞必须一字不差；
   解释性列表不得把后文才揭示的关键词提前泄入。
5. **标点与格式**：外层引号用「」、内层『』，禁用弯引号；旁白是否凭空加引号、对白是否
   丢引号（判据是与原文对齐）；Siglus 无换行记号，故"断行位置"维度不存在，但要注意
   单串过长导致的折行观感问题（真机抽查）。

### 4.2 工具与产物

```bash
python scripts/make_proof.py unpacked/a.ss work/a.tsv proof/a.tsv
#   → proof/a.tsv          六列对照稿（索引/说话人/原文/初译/校对/备注）
#   → proof/a.preview.txt  剧情顺序纯文本：当读者通读文气/术语一致性/上下文衔接
#   → proof/a.read.txt     带索引对照稿 #索引 [说话人] 原文 ⇒ 生效译文：当校对逐句精读
python scripts/edit_proof.py proof/a.tsv <索引> "<改稿>" ["<批注>"]   # 单条；--file 批量JSON
python scripts/check_punct.py proof/*.tsv                            # 引号/标点规范自查
python scripts/merge_proof.py work目录 proof目录                      # 改稿回合 work（proof 留存）
```

- 两份阅读稿共用同一套生效译文（初译 ∪ 既有改稿），重跑幂等、批注按索引保留。
- edit_proof 对真实换行直接拒绝（防 TSV 拆坏）；给出键才写入、空串清列、未命中退出码 1。
- 校对员只动 proof 第 5/6 列；rebuild 可直接吃 work+proof（校对优先自动生效），也可先
  merge_proof 回合再仅用 work 重建（两者结果一致）。

### 4.3 逐句精读易翻车硬伤类型

- **指代与方向**：「〜の〜」所有格谁属谁、动作施受方向——错译文往往"读起来顺"，
  只有对照原文才能发现，优先扫。
- **否定辖域**：「〜ない限り」＝除非…；否定式惯用句按逻辑等价改写，不要逐字直译。
- **声纹不只拟声词**：第一人称自称、语尾习惯、敬语水准都是声纹；跨章搜索各角色的自称
  代词是否漂移。
- **拟声词分级统一**：招牌多拍笑声一字不差；短促感叹音允许少量变体并有记录。
- **解释性列表是泄密高发区**："别名一览"式句子不得混入后文关键词。
- **数字逐处核对**：价格、卷数、日期是时间线刻度。
- 原作笔误按意图翻译即可，不必仿写，记录备查。

## 5. 重建 → 验证 → 封包

```bash
# 逐文件重建（work 在前 proof 在后 = 改稿优先），verify 必须 MATCH
python scripts/ss_tool.py rebuild unpacked/a.ss out/a.ss work/a.tsv proof/a.tsv
python scripts/ss_tool.py verify  unpacked/a.ss out/a.ss work/a.tsv proof/a.tsv

cp out/*.ss unpacked/                       # 只覆盖改动过的场景
python scripts/pck_tool.py pack Scene.pck Scene_new.pck unpacked/ --key-file workspace/key.txt
# 回读验证: 解包回去逐文件内容级比对
python scripts/pck_tool.py unpack Scene_new.pck /tmp/vfy --key-file workspace/key.txt
```

发布前最后过一遍真机 QA：抽若干章对白、翻页节奏、既读判定、自动模式、快进跳过；
检查折行观感与字体缺字（简体字形缺失时考虑换字体或繁体表记）。

## 6. 已知事故模式（历史教训速查）

| 症状 | 根因 | 预防 |
| --- | --- | --- |
| 解压报非法回引 / 压缩长不符 | 游戏密钥错误 | probe 先行；见 pck-format.md §3 |
| verify 报 ASCII 结构串被改动 | 把命令名/标识符当文本翻了 | 用模板（已过滤）而非 strings --all 兜底导出 |
| verify 报字符串数量不符 | 手工增删了 TSV 行 | 索引是唯一锚点；以模板重生成骨架 |
| 台词在游戏中显示 \n 字样 | 误写了字面换行记号 | Siglus 无此机制，删掉；rebuild 会拦 |
| 汉化后**部分**文本叠字、或简体字变方框 | 消息用**系统日文字体**缺简体字形 → 字体回退破坏等宽排版 | 换 exe 让引擎按中文排布（japanese→chinese）+ 确认消息字体；详见 rendering-fonts.md |
| 整段译文错位 | 把行号当索引用 | 改稿前 awk 回验目标行 |
| TSV 被"悄悄拆坏" | 字面 \n 被工具解码成真实换行 | 解析器对首列非整数**致命报错**；交付前集中 check_structure |
| 回封后部分场景读不出 | manifest 槽位被手工增删/改名 | 只用 unpack 原产物目录封包 |
| 终检误报/漏报 | 终检脚本自身有 bug | 先用已知好样本回归出零差异再信任 |

## 7. 多代理并行分派（大工程实测纪律）

适用：章节多、条目数以万计的完整汉化工程。核心矛盾是**吞吐 vs 一致性**——解法是
"简报固化术语 + 按章切分互不依赖 + 集中终检兜底"，三者缺一不可。

1. **简报先行（BRIEF）**：原料即 §1 的梗概/指南/terms.tsv；至少包括硬性格式规则
   （只填最后一列；不写任何换行记号；行宽预算；全角标点与全角英数；引号规范）、术语总表
   与称呼对照（宣布全程冻结）、高风险场景规则、各章剧情上下文摘要。
   没有简报就开并行，返工成本必然高于写简报。
2. **按章切分、高并行**：每个 .ss 一个执行者互不依赖，实测一次 10+ 可行；提示里给全
   "步骤 + 本章要点 + 硬性规则 + 自查命令 + 汇报格式"；超长章明确"逐条完成不得跳行漏译"。
3. **超时与重派**：超时≠失败——先查工作区文件实际进度（已填多少条），对未完成或损坏的章
   原样重派，重派提示里写进上次的失败教训。
4. **不信任自报，集中终检**：全部汇报完成后由主控统一跑 validate_text（逐文件退出码全 0）
   → check_structure（全量 vs tpl）→ check_terms；终检脚本自身先用已知好样本回归再信任。
5. **一致性抽查**：跨章搜索同一术语/称呼的表记是否一字不差；回环台词逐处比对。
