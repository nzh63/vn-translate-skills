# .ss 场景脚本格式与字符串回写

> 适用：SiglusEngine 场景数据库内解出的 `.ss` 脚本。
> 工具：`scripts/ss_tool.py`（info / strings / rebuild / verify）。

## 1. 文件布局（实测存在两种变体）

```
u32 头部长(=132)
u32 ×32 头字段（常用位）:
  [2] 字符串表偏移(=132)   [3] 条目数
  [4] 字符串数据区偏移     [5] 条目数（重复）
  [0] / [6..30 偶数位]     其它区段偏移（布局相关，见下）
字符串表 @132: 条目数 × (u32 词偏移, u32 词长)    ← 偏移/长度单位都是 2 字节"词"

变体A（銀色、遥か）: [头][表][字符串数据区][字节码尾块]   hdr[0]=尾块起点
变体B（另一实测样本）: [头][表][字节码……各区段][字符串数据区]  hdr[0]=字节码起点，
                      hdr[4] 指向文件末尾的字符串区
```

工具不假设物理顺序：一律按头字段寻址。字符串区的边界 = hdr[4] 到"比它大的最小
偶数位头字段"（无则到文件尾）。rebuild 采用**外科替换**策略：只重写字符串表与
字符串数据区两块内容，其余字节一律不动；新旧串流不等长时，字符串区之后的全部
内容整体平移差值，所有压在边界/其后方的偶数位头字段同步平移。恒等重建（译文=
原文）产物与原文件逐字节一致——这是 rebuild 正确性的回归标准。

## 2. 字符串混淆

第 `i` 条字符串的每个 UTF-16 码元与 `(28807 × i) % 65536` 异或——**按索引自派生，
无密钥**。因此：条目顺序绝对不能变（一变全部解错）；回写时用同一公式重新异或即可。
非 BMP 字符（码元 > 0xFFFF）引擎无法存储，rebuild 直接拒绝。

## 3. 文本特征（提取与翻译必读）

- **索引序 = 剧情序**。旁白、说话人名、对白在表里按演出顺序排布；
  模板/阅读稿都按升序走，译者从上往下读就是剧本。
- **说话人名通常是对白的前一条**：形如 …`雛多` → `「セリフ」`。
  `make_template` 用启发式（短 + 无引号 + 下一条以「开头）把人名填进说话人列。
  启发式会漏/误判，但只影响展示参考，不影响重建数据。
- 对白还有 **【名字】「台词」合一形态**（说话人列为空，名字在文本里），翻译时保留结构。
- **％Ａ / ％Ｂ / ％ 开头的串是控制标记**（翻页、语音挂接等）：不进模板、绝不可译。
  纯 ASCII 串是命令名/标识符等脚本结构，同样不可动。
- **没有换行记号机制**：消息窗自动折行，翻页靠独立的 ％Ｂ 标记串。译文写 `\n`
  或字面 `\n` 都会被 rebuild 拒绝——前者会把 TSV 拆坏，后者会在游戏里原样显示。
- 行宽上限逐作不同，首次适配必须真机实测后固化为 `validate_text --width=N --lines=1`
  （Siglus 是单串自动折行，按"总长预算"门禁而非行数）。

## 4. 回写流程（原文件只读）

1. 解析字符串表 → 按 TSV 索引替换内容；**索引越界或日文原文不符立即拒绝**（防错位）。
2. 全部字符串长度都不变 → **原位覆盖**：产物与原文件逐字节同构（只有目标串的字节变了）。
3. 有长度变化 → **外科替换**：重写字符串表（新偏移/长度）与字符串数据区两块，
   字符串区之后的全部内容整体平移长度差，相关偶数位头字段同步平移。
   布局次序（变体A/B）与所有其它区段保持原样。
4. 表序与数量不变 → 脚本逻辑零改动。

## 5. 验证门禁（封包前必过）

`ss_tool.py verify <orig> <new> <tsv...>` 做**内容级**比对：

- 新文件每个字符串 == 「原表 + TSV 生效译文」的预期结果（数量不变）；
- ASCII 结构串零改动；
- 字节码尾块零改动（rebuild 只许动字符串）。

⚠ 只验"能解析"是不够的。凡改动验证/回写逻辑，先用已知样本回归出"恒等重建=逐字节一致"，
再信任它对坏样本的判罚（`_selftest.py` 已固化此回归项）。
