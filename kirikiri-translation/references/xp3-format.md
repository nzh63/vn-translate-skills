# XP3 封包格式与适配笔记

> 目标读者：需要解包/封包 KiriKiri 系游戏 `.xp3` 的执行者。先 `probe`，再动手。

## 1. 标准 XP3 布局

```
0x00  魔数 11 字节: 58 50 33 0D 0A 20 0A 1A 8B 67 01 ("XP3\r\n \n\x1a\x8b\x67\x01")
0x0B  u64 版本 (krkr2=0x17, krkrZ/Suite=0x02)
0x13  u64 索引区偏移
...   文件数据区（各文件 blob 的绝对偏移记录在 segm 中）
索引  [01][u32 zlen][u32 ilen][zlib(表)]   或 [02][u32 len][裸表]
      表 = File 条目流: [4CC"File"][u64 大小][子块流]
      子块: [4CC][u64 大小][内容]，常见 adlr / segm / info / time（顺序不限）
        info: [u32 flags][u64 原始大小][u64 打包大小][u32 文件名长(字符)][文件名 UTF-16LE]   —— 头 24 字节
        segm: [u32 压缩标志][u64 数据偏移][u64 原始大小][u64 打包大小]
        adlr: [u32 adler32(解压后内容)]
        time: [u64 时间戳]（可省略）
```

## 2. 常见定制/混淆变体

不少商业作品会混淆魔数区与索引布局以对抗通用工具。已观察到的变体特征（`xp3_tool.py probe`
能自动识别）：

- **头部加宽到 40 字节**：魔数区字节被替换/插入垃圾，但前 11 字节仍以 "XP3" 开头；
  索引偏移字段从 @0x13 挪到 @0x20。
- **索引带 pad**：`[01][u32 zlen][pad4][u32 ilen][pad4][zlib(表)]` → zlib 流前要跳过 17 字节。
- **info 紧凑布局**：`[u32][u32 orig][u32][u32 comp][u32][u16 namelen][name]`（头 22 字节，
  宽度全部砍成 32 位）。

探测顺序：候选索引偏移 {0x13, 0x20} → 读到文件尾 → 找第一个使 zlib 解压成功且表头为
`File` 的跳过长度。info 布局按"头部长度 + 名字长度×2 == 子块大小"校验自动判别。
遇到全新变体：hexdiff 两三个已知样本的头部；索引一定在文件尾，从尾部反推。

`.sig` 文件是官方完整性检查工具的签名，运行时不参与加载，通常无需理会。

## 3. patch.xp3 挂载行为（必须逐项实测）

KiriKiri 引擎原生支持读取游戏根目录下的 `patch.xp3` 并**优先于** data.xp3 命中同名条目，
原版包无需改动。但具体行为因引擎魔改而异，首次适配用伪翻译补丁冒烟验证以下每一项：

| 检查项 | 常见情况 | 验证方法 |
| --- | --- | --- |
| 头部格式 | 定制魔数的游戏通常要求补丁同款头部 | 用 `--template data.xp3` 封一版对比标准版 |
| 条目命名 | 有的按根目录裸名查询剧本（带目录前缀会静默回退日文！），有的保留相对路径 | 两种各封一版进游戏看是否生效 |
| 数据压缩 | 定制版常只认 stored；标准版两者皆可 | stored 版最稳 |
| 运行模式 | 游戏以 PACKED 模式运行时不读文件系统，散文件覆盖无效 | 放一个散文件对照 |
| 加载优先级 | patch > data；未改动文件由 data 提供 | 只打包改动过的文件即可 |

伪翻译冒烟：把某章文本整体替换成可辨识的假文（如全角Ａ），封补丁进游戏确认显示，
再换真译文——避免"翻译完才发现链路不通"。

## 4. 整包重建（兜底路线）

深度汉化（字体/UI/系统文本）或补丁路线走不通时，可用 pack 默认模式整包重建 data：
解包 → 替换目标文件 → 重打包（模板匹配原版布局）。**动 data 前务必备份原版**；
重建后先做回环验证（重解包逐文件比对 adler32 与字节数），再上真机。
