# KiriKiri 系游戏文本汉化 · 完整流程手册

> 从零到可发布 patch.xp3 的标准链路。所有原版文件全程只读，产物一律写新文件。
> 格式细节见 `xp3-format.md` 与 `psb-scn-format.md`；本文只讲流程与纪律。

```
game data.xp3 ──(1) xp3_tool unpack──▶ unpacked/
unpacked/*.scn ──(2) make_template──▶ tpl/(原文,只读) + work/(译文骨架)
unpacked/*.scn ──(2b) extract_text──▶ text/(剧情顺序可读全文，译者语境)
work ──(3) 初译（只填最后一列；多章可多代理并行，见 §7）
work ──(4) validate_text──▶ 行宽门禁
work ──(5) make_proof──▶ 对照稿 proof + preview/read 两份阅读稿 ──(6) 人工校对（改稿列+批注列）
work+proof ──(7) validate_text──▶ 终校门禁（必须全绿）
全部章节交付后: validate_text(逐文件) + check_structure(--tpl 全量) + check_terms ──▶ 结构/术语终检
原scn + work + proof ──(8) psb_tool rebuild──▶ 译好的 scn
        (9) psb_tool verify──▶ 内容级验证（必须 MATCH）
译好的 scn ──(10) xp3_tool pack --patch──▶ patch.xp3 ──▶ 游戏根目录
        (11) 回读验证 + 真机抽查
```

## 0. 首次适配清单（新游戏必做）

1. `xp3_tool.py probe` 确认封包格式；解包后确认 adler32 全过。
2. 用 psb_tool 定位文本所在文件与结构（texts 表？lines 直引？系统文本在哪）。
3. **实测引擎硬限制**：每行字数 × 行数上限、可用字符集/字体覆盖范围。
4. 小规模伪翻译冒烟：1~2 个文件的假译文走完全链路进真机，确认补丁挂载行为
   （裸名 vs 相对路径、stored vs 压缩、头部格式），全部结论记入项目笔记。
5. 确认既读判定/跳过不受影响（履历版派生一致性）。
6. 译前通读与指南生成（见 §1）：导出可读全文，产出剧情梗概/翻译指南/terms.tsv 后再开翻。

## 1. 译前通读与指南生成（开工前必做）

> 目标：把"全书视野"沉淀为三份产物——**剧情梗概、翻译指南、terms.tsv**，
> 让后续分章翻译的执行者不需要（也不应该）拥有全书上下文。

为什么必做：

- 术语/称呼一旦在初译中各自漂移，校对期统一返工的成本远高于开工前定名。
- 伏笔、双关、叙事诡计、跨章回环梗（某句台词/某个数字反复出现作时间刻度之类）
  只有通读全书才能被发现，并写成硬规则。
- 分章译者若直接拿全书文本，容易把后文才揭示的信息提前泄露进前文译文（破坏叙事
  诡计）。正确做法：全书知识浓缩成规则放进指南，译者只读本章 + 简报。

做法（少量代理即可，与翻译阶段的 10+ 并行不同）：

1. `extract_text` 导出按剧情顺序的可读全文（每章一个文件）。
2. 分派少数"读者"代理逐章/逐数章通读，按固定结构汇报：分章梗概（数句）、出场人物
   与称呼、新术语提案（`原文\t建议译文\t依据`）、伏笔/双关/回环标记、疑难句。
3. 主控汇总各章报告：合并去重术语提案并**统一定名拍板**（多个提案冲突时按
   字面/读音/作品内互文优先级裁决），产出：
   - **剧情梗概**：分章摘要、人物关系、伏笔与叙事诡计清单、时间线；
   - **翻译指南**：术语总表、称呼对照、角色声纹（自称/语气/口癖/笑声）、文体规范、
     高风险场景处理规则、回环梗清单；
   - **terms.tsv**：指南术语表的机器可读版（`原文\t规范译文[\t禁用形式]`），
     直接作为 `check_terms.py` 的门禁输入。
4. 三份产物即《翻译简报》（BRIEF）的原料；之后的并行分派见 §7。

⚠ 读者代理需要**全书视野**（剧透无妨），译者代理恰恰相反——两个阶段的上下文策略
相反，正是它们必须分开的原因。

## 2. 工作区与三分离设计

| 目录 | 内容 | 纪律 |
| --- | --- | --- |
| unpacked/ | 解包产物 | 只读。任何脚本不得写回 |
| tpl/ | 原文模板（索引\t说话人\t日文） | 只读参考，可随时重生成 |
| work/ | 译文文件（…\t日文\t译文） | 译者只填最后一列；生成器绝不覆盖已存在文件 |
| proof/ | 对照稿（索引\t说话人\t日文\t初译\t校对\t备注）＋ preview/read 两份剧情顺序阅读稿 | 校对只动第5/6列；第5列留空=采用初译 |
| out/ 或 patch_files/ | 重建产物 | 可随时删除重来 |

- 生效译文规则统一为：**校对列非空 > 初译列**；多文件合并时后者按索引覆盖前者。
- 模板可反复重生成；work 损坏时可用 tpl 按索引重建骨架。

## 3. 翻译阶段纪律

- **索引是唯一锚点**：TSV 第 1 列才是字符串表索引。批量改稿前用 `awk -F'\t' '$1==N'`
  回验目标行内容——曾发生把"查看器行号当索引"写入导致整段错位的事故。
- 换行用字面 `\n` 记号，它是字面两个字符（反斜杠+n）。**写入纪律（实测高频事故）**：
  禁止经 shell/heredoc/命令行内联直写译文——`\n` 极易被解码成真实换行把 TSV 行拆散；
  一律用脚本文件 + raw 字符串（或转义反斜杠）写；写完跑 check_structure 兜底。
  未译条目也要保持列数（留空的最后一列），否则旧格式兼容逻辑会把日文原文误当译文。
- 行宽在语义停顿处断；数量不必与原文一致但不得超限；全角标点；译文宜短于或等于原文。
- 全角英数字母/数字保持全角（与原版 UI 宽度匹配）；说话人列为空＝旁白/独白（多为第一人称
  内心），语气归属以它为准。
- 术语表先行：角色名/自称/拟声词（角色声纹）/专有名词/回环台词建立对照表并全程冻结；
  同一台词跨章重复出现时措辞必须一字不差（回忆回环梗）。冻结用 check_terms 落地为门禁，
  不要靠人眼。
- 伏笔与叙事诡计保护是通用原则：后续章节才揭示的信息，前文译文与注释都不得提前泄露；
  需要显眼的伏笔句按简报要求处理。译者注只在"不加注就无法理解"时使用，格式统一且从简。
- 引号规范示例（按目标 UI 习惯定稿）：对白外层「」、内层引用『』；旁白不加「」；
  弯引号 " " ‘ ’ 一律替换。

## 4. 校对阶段

### 4.1 校对总清单（五个维度，缺一不可）

1. **信达雅**：语句是否忠实原意、通顺自然、有雅韵——拒绝机翻腔（逐字直译、"的/了/吧"
   连篇、欧化长句）；原文俏皮处要译出笑点，抒情处要有相应的节奏与韵味。
2. **上下文与人称**：上下文是否通畅；人称指代是否正确（谁属谁、谁对谁做）；行文是否
   符合说话人的性格（自称、语气、敬语水准等角色声纹）。说话人列为空＝旁白/独白。
3. **译法一致性**：不同译者对同一个词（特别是专有名词、术语、称呼）是否产生了多种译法
   ——用跨章搜索逐一比对并统一为定稿。
   **例外**：语气词，以及依据人物性格刻意使用不同表述时，允许合理差异；宽容尺度写入
   项目笔记（如某角色的招牌多拍拟声一字不差，短促感叹音允许少量变体）。
4. **伏笔 / 谐音 / 双关 / 梗**：是否按翻译指南正确处理；跨章回环呼应句措辞必须一字不差；
   解释性列表不得把后文才揭示的关键词提前泄入（见 §4.4）。
5. **标点与换行**：是否符合中文使用习惯——
   - 行末无标点的换行**有时暗示**（但不绝对）标点缺失或换行误用，需人工复核；
   - 外层引号用「」、内层引用用『』，禁用弯角引号 " " ‘ ’；
   - 旁白是否凭空加了引号、对白是否丢了引号（判据是与原文对齐，自动化见 §4.5）。

§4.2–§4.4 是维度 1–4 的落地手法与易翻车模式，§4.5 是维度 5 的自动化。

### 4.2 工具与产物

```bash
python scripts/make_proof.py scn/A.scn work/A.tsv proof/A.tsv
#   → proof/A.tsv          六列对照稿（索引/说话人/原文/初译/校对/备注）
#   → proof/A.preview.txt  剧情顺序纯文本，无索引：通读文气、术语一致性、上下文衔接
#   → proof/A.read.txt     剧情顺序带索引对照稿：每条两行
#                             #索引 [说话人|旁白] 日文原文        （字面 \n 记号原样保留）
#                                   ⇒ 生效译文                    （字面 \n 显示为 ⏎）
#                          场景间有分景线；不在字符串表内的行标 ????
python scripts/edit_proof.py proof/A.tsv <索引> "<改稿>" ["<批注>"]   # 单条；--note 只加批注
python scripts/edit_proof.py proof/A.tsv --file edits.json            # 批量 [{"i":..,"fix":..,"note":..}]
python scripts/check_punct.py proof/*.tsv                             # 引号/标点规范自查
python scripts/merge_proof.py work目录 proof目录                      # 改稿回合 work（proof 留存，幂等）
```

- **两份阅读稿的分工**：preview 无索引、贴 UI 排版，适合"当读者"通读——抓文气断裂、
  上下文指代错位与跨章译名漂移；read 每条自带字符串表索引，适合"当校对"逐句对照原文，
  看到问题直接按 #索引 改稿。两者同源于同一套生效译文（初译 ∪ 既有改稿），重跑
  make_proof 幂等地同步刷新，改稿批注列按索引保留。
- **edit_proof 纪律**：索引是唯一锚点；JSON 里字面换行记号要写 `"\\n"`——脚本会**拒绝**
  含真实换行的内容（防止 TSV 被拆成两行，见 §6 事故表）；给出键才写入、键值为空串即清除
  该列、未给出的键保持不变；存在未命中索引时退出码为 1，可据此脚本化确认。
- 校对员只动 proof 第 5 列（改稿，留空=采用初译）与第 6 列（批注）；rebuild 可直接吃
  work+proof（校对优先自动生效），也可先 merge_proof 回合再仅用 work 重建（两者结果一致）。

### 4.3 对照稿怎么读

- preview 一遍当读者：只看译文能否独立成立，标记"读着别扭"的位置（多半是直译腔或指代断线）；
- read 一遍当校对：逐句对照原文，重点扫 §4.4 列出的硬伤类型；说话人列为空＝旁白/独白，
  语气归属以它为准。
- 两遍的产出都落到第 5/6 列；批注写"为什么改"，供下一轮校对与主控复核。

### 4.4 逐句精读清单（维度 2–4 的易翻车硬伤类型）

- **指代与方向**：「〜の〜」所有格谁属谁（主宾颠倒）；动作谁施加给谁（施受方向读反）。
  这两类错译文读起来"顺"，只有对照原文才能发现，优先扫。
- **否定辖域**：「〜ない限り」＝除非…；"没有很好的X"≠"很差的X"。否定式惯用句应按逻辑
  等价改写成中文语序，不要逐字直译。
- **声纹不只拟声词**：第一人称自称、语尾习惯、敬语水准都是角色声纹。跨章搜索各角色的
  自称代词是否漂移——某角色的专属自称被别的角色借用就是串味。
- **拟声词分级统一**：角色的招牌多拍笑声一字不差；短促感叹音允许少量合理变体，但同一角色
  同一声不宜超过两种写法，宽容尺度写入项目笔记。
- **解释性列表是泄密高发区**："别名一览""叫法有这几种"式的句子，不得把后续章节才揭示的
  关键词混进列表——伏笔要在正式点题处引爆，列表提前泄名等于剧透。
- **数字逐处核对**：价格、卷数、账号、日期是时间线的刻度，加总与前后文互证后再放行。
- **原作笔误**：官方文本的错字/人名表记不一，按意图翻译即可，不必仿写，记录备查。
- 纯符号行（？！之类）不在模板内属正常——游戏显示日文原串即为所需，不要为此扩模板。

### 4.5 自动化自查与复验（维度 5 的机器部分）

- `check_punct` 五类检查：引号配平（「」『』计数相等）、弯引号/直引号残留、凭空加引号
  （旁白且原文无「而译文有「）、凭空丢引号（原文有「而译文没有）、CJK 文本混入半角点号
  （前一字符非 ASCII 才报，"OK," "1,000" 不算）。判据是"引号与原文对齐"而非说话人本身
  ——旁白转述台词时原文自带引号，保留是正确的。
- `validate_text` 复查行宽。译文行末无标点的换行需人工复核（可能漏标点或误断行），
  但游戏文本有意无标点断行也常见——只提示不阻断。
- 机械替换会产生二次产物（如先删半角破折号再查全角句号），多轮扫描要交叉复验。

## 5. 重建 → 验证 → 封包

```bash
# 逐文件重建（work 在前 proof 在后 = 改稿优先）
python scripts/psb_tool.py rebuild unpacked/scn/A.scn out/A.scn work/A.tsv proof/A.tsv
# 内容级验证（门禁）
python scripts/psb_tool.py verify  unpacked/scn/A.scn out/A.scn work/A.tsv proof/A.tsv
```

```bash
mkdir -p patch_files && cp out/*.scn patch_files/     # 按冒烟验证确认的命名方式放置
python scripts/xp3_tool.py pack patch_files patch.xp3 --patch --template <data.xp3>
# 回读验证: 解包回去逐字节比对
python scripts/xp3_tool.py unpack patch.xp3 /tmp/vfy && diff -r patch_files /tmp/vfy
```

发布前最后过一遍真机 QA：抽若干章对白、履历（backlog）、既读判定、自动模式、
快进跳过；检查换行断点观感与字体缺字（简体字形缺失时考虑换字体或繁体表记）。

## 6. 已知事故模式（历史教训速查）

| 症状 | 根因 | 预防 |
| --- | --- | --- |
| 进某章即崩/异常对话框 | 字符串偏移数组宽度标记与实际字节不符（0x0F=3B 写成 4B） | 内容级 verify（§5）；见 psb-scn-format.md §2 |
| 补丁不生效且无报错 | 条目带目录前缀而引擎按裸名查询，静默回退日文 | 冒烟阶段确定命名约定 |
| 整段译文错位 | 把行号当索引用 / 机械平移 | 改稿前 awk 回验目标行 |
| 台词在游戏中被截断，且无任何报错 | `\n` 记号被工具解码成真实换行，一条记录被拆成多个物理行，解析器把续段**静默丢弃** | 解析器对"数据行首列不是整数"必须**致命报错**而非跳过；修复=把记录的物理行用真实 `\n` 拼回、按 tab 重新切列、字段内真实换行转回字面记号 |
| 履历/跳过判定异常 | 履历副本未同步派生 | 保持 rebuild 默认派生开启 |
| 修完 A 又冒出 B | 机械替换产生二次产物（如先删半角破折号再查全角句号） | 多轮扫描交叉复验 |
| 终检误报/漏报 | 终检脚本自身有比对 bug（如把解析器返回的元组当列数组用） | 终检脚本先用已知好样本回归出"零差异"，再信任它对坏样本的判罚 |

## 7. 多代理并行分派（大工程实测纪律）

适用：章节多、条目数以万计的完整汉化工程。核心矛盾是**吞吐 vs 一致性**——解法是
"简报固化术语 + 按章切分互不依赖 + 集中终检兜底"，三者缺一不可。

1. **简报先行（BRIEF）**：简报的原料即 §1 译前通读产出的梗概/指南/terms.tsv；内容至少包括：
   - 硬性格式规则（只填最后一列；`\n` 是字面两字符、必须脚本文件+raw 字符串写入；
     行宽/行数上限；全角标点与全角英数；引号规范）；
   - 术语总表与称呼对照（人名、地名、专名、拟声词=角色声纹、回环台词），宣布"全程冻结"；
   - 高风险场景规则（伏笔不得提前泄露、双关处理方案、必须显眼的句子清单）；
   - 各章剧情上下文摘要（避免执行者因缺语境而译偏）。
   没有简报就开并行，返工成本必然高于写简报。
2. **按章切分、高并行**：每章一个执行者，互不依赖可同时开工（实测一次 10+ 可行）；
   提示里给全"步骤 + 本章要点 + 硬性规则 + 自查命令 + 汇报格式"。超长章（数百条以上）
   要明确"逐条完成不得跳行漏译"，否则容易被截断收尾。
3. **超时与重派**：长章可能超出单次执行时限。超时≠失败：先查工作区文件实际进度
   （已填多少条），对未完成或损坏的章原样重派即可；重派提示里把上次的失败教训写进去
   （例如"`\n` 必须转义，曾因此损坏文件"）。
4. **不信任自报，集中终检**：执行者的自检不可靠——实测约三分之一会踩 `\n` 转义坑，
   多数能自行修复但仍有漏网。全部汇报完成后由主控统一跑：
   `validate_text`（逐文件退出码全 0）→ `check_structure`（全量 work vs tpl）→
   `check_terms`（术语冻结）。终检脚本自身也要先用已知好样本回归再信任（见 §6 末行）。
5. **一致性抽查**：跨章搜索同一术语/称呼的表记是否一字不差；回环台词逐处比对。
   这一步抓的是简报没写死、执行者自由发挥造成的漂移。
