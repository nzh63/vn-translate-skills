# Hy-MT2 指令工程（Galgame 场景）

## 1. 官方指令模板

Hy-MT2 **没有默认 system prompt**，全部内容塞进一条 user 消息即可。`mt_common.build_prompt`
按官方模板拼装，四类指令可叠加：

| 类型 | 模板 | 本技能开关 |
| --- | --- | --- |
| 默认翻译 | `将以下文本翻译为{目标语}，注意只需要输出翻译后的结果，不要额外解释：` | 总是带 |
| 术语干预 | `参考下面的翻译：\n{原文}翻译成{译文}\n…` | `--terms terms.tsv` |
| 风格 | `注意翻译的风格要严格符合【**{风格}**】` | `--style "日常口语化"` |
| 背景信息 | `【背景信息】…\n\n【待翻译文本】…` | `--context N` |
| 个性化 | `【翻译任务】1、… 2、… 3、将【待翻译文本】翻译为{目标语}。` | `--extra "…"`（可重复） |

> 批量翻译**不用分隔符拼接**：每条原文各自成一条 prompt，整批交给 tokenizer 的
> left-padding 在**一次前向**里推进（`--batch` × `--micro-batch` = 单次并行条数）。
> 因此不存在"模型少输出一个分隔符导致整批降级"这类失败。

推荐采样参数（`translate_tsv.py` 已内置）：

```json
{"temperature": 0.7, "top_p": 0.6, "top_k": 20, "repetition_penalty": 1.05}
```
30B-A3B 用 `top_p=1.0, top_k=-1, repetition_penalty=1.0`（脚本按模型名自动切）。

## 2. 术语表

格式与三个引擎技能的 `check_terms.py` **完全一致**，一处维护两处用：

```
# 术语表（Tab 分隔，# 注释）
原文片段	规范译文	禁用形式1,禁用形式2
サクラ	樱/H/	櫻
ラーメン	拉面
エッチ	色/H/做爱
```

- 规范译文用 `/` 分隔多候选；喂给模型时只取第一个候选。
- **只把当前批次原文里出现过的术语塞进 prompt**（`filter_terms`），
  省 token 也避免无关术语污染译文。上限 `--max-terms 40`。
- 术语表该由"译前通读"阶段产出并全程冻结，不要边翻边改。

## 3. 换行与标签：本技能的核心保护

引擎 TSV 里有两类**结构记号**，一律不可译、不可丢、顺序不可变：

1. 行内标签 `[r]`（换行）`[p]`（翻页）`[vs]`… —— Tyrano 系
2. 字面 `\n` 记号（反斜杠 + n 两个字符）—— KiriKiri / Siglus 系

处理流程（`mt_common.protect` / `restore`）：

```
原文   「ああ[r]そう」 + 字面\n
   ↓ protect
遮蔽   「ああ⟨0⟩そう」⟨1⟩        + tags=['[r]', '\\n']
   ↓ 送模型（附指令：⟨数字⟩ 占位标记原样保留，数量顺序完全一致）
译文   「啊啊⟨0⟩是的」⟨1⟩
   ↓ restore
落地   「啊啊[r]是的」 + 字面\n
```

译后校验 `tags_of(译文) == tags_of(原文)`，不一致 → 该条自动降级为"单条重译"，
仍不一致 → 留空并写进 `--failed`。

`⟨⟩` 是训练分布内常见的"不可翻译占位"写法（官方 Structured Data 指令里明确要求
保留 `{{var}}`/`%s` 之类占位符）。如果某批译文把 `⟨0⟩` 写成了 `<0>` 或 `〈0〉`，
`restore` 也能认（正则同时接受三种括号），只有编号越界才判失败。

## 4. 常用开关组合

```bash
# 保守默认：准确性优先，不带上文
--batch 8 --micro-batch 4 --context 0

# 质量优先：带上文 3 条（指代/口吻更连贯，token 约翻倍）
--batch 8 --context 3

# 长句剧本 / narration 多：减小批量并给足输出长度，避免译文被截断
--batch 4 --micro-batch 2 --max-new-tokens 512

# 可复现（做 A/B 对比指令时）：
--greedy

# 跳过名字行（Tyrano 的 【ユリ】 之类）
--skip-regex '^【[^】]*】$'

# 只翻某个文件的前 50 条看效果
--limit 50
```

## 5. 失败条怎么处理

`_mt_failed.tsv` 每行是 `文件名 \t 行位 \t 原文`。常见原因：

- 原文超长，模型截断输出 → 拆条或调大 `--max-new-tokens`
- 原文是纯拟声词/符号 → 手工补
- 原文含模型没见过的奇怪标签 → 手工补，或加 `--skip-regex` 排除

补完直接把值填进 TSV 对应格即可，重跑脚本会自动跳过已译条目。
